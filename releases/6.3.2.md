# 6.3.2 — Separate microphone and system audio, first custom release

Unofficial custom firmware for the **HiDock H1E only**, built on official H1E 6.3.0. It is Sebastián's own build, not an official HiDock release.

This is the first custom audio build. [6.3.4](6.3.4.md) has the same recording code and is the recommended build. 6.3.2 is retained as the previous released image; new installations should use 6.3.4.

## Recording changes compared with official 6.3.0

- Microphone and system audio are kept as two channels instead of one mono mix made before encoding. Channel 1 (left) is the microphone and Channel 2 (right) is the system audio.
- Choose stereo MP3 or 16-bit stereo WAV, both at 16 kHz.
- MP3 profiles give a total rate of 64, 96, 128 or 160 kb/s. That is 28.8, 43.2, 57.6 or 72 MB per hour. WAV is 64 kB/s, about 230.4 MB per hour. Sizes leave out headers and footers.
- Each channel has its own recording gain from 0% to 200%. 0% is silent and 100% is unchanged. Gain affects the saved file only, not USB conferencing volume or the mic mute.
- Settings are written to the dock's own nonvolatile storage, so they stay on the dock and not in the app.
- The hardware marker button still works. Connected apps and programs can add markers, and the dock can add them on its own from sound level, with a threshold, a lane (first, second or either channel), a 100 ms onset, a 100 ms re-arm and at least 10 seconds between markers. Automatic markers are off by default. Markers are saved in the file footer.

Full tables, limits and checks are in the [6.3.4 notes](6.3.4.md).

## Repairs to USB handling and the file list

| Change | What it means for you |
| --- | --- |
| USB requests are checked before use: framing, lengths, paths and arithmetic | A malformed request is refused, or dropped with no reply. A client must treat a timeout as a failure |
| File names in commands limited to 1 to 27 printable ASCII characters, with no path separators, colon or `..` | A command cannot point outside the recordings folder |
| Multi-part requests read their full 32-bit sequence and length | Long transfers are tracked correctly |
| File-list entries have their reserved bytes zeroed | Leftover memory no longer shows up in the list |
| The checksum over the start of a file covers the bytes actually read | Files shorter than a read block, such as 1, 511, 513 or 1023 bytes, previously got a wrong checksum from stale buffer data |
| Several console configuration commands reject missing or null arguments | They return an error instead of acting on bad input |
| Memory held for a multi-part request is released on errors, aborts and cleanup | Failed requests no longer leave buffers behind |

The dock also gains a small read-only console report: help, version and uptime. It is not a shell and does not expose the serial port.

These repairs were checked by running the patched firmware code against 377 bounded request/parser cases offline, including malformed inputs. They have not been tried case by case on a dock. The image has booted and recorded on a physical dock.
